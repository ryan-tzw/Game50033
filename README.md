# Crescendo (50.033 Game Design and Development)

A music-themed, 2D top-down boss rush for 2–4 players in local co-op. See `50.033 GDD.pdf` for the full design.

- **Unity:** 6000.3.24f1 (URP)
- **Scene flow:** `Lobby` → `Cutscene1` → `BossOneScene` (dog boss) → `Cutscene2` → `MafiaTest` (Mafia boss) → back to `Lobby`. All of these are in Build Profiles. Open `Lobby` and press Play to go through the whole flow. `Game.unity` is no longer part of the run. The main menu isn't built yet; it will go in front of `Lobby`.
  - The order lives in `Assets/Tuning/Flow/GameFlow.asset`. Each scene has a `GameManager` that loads the next one.
  - `Cutscene1` and `Cutscene2` are the same placeholder: each fades the word "Placeholder" in and out, then loads the next scene.
  - Players who joined in the lobby are carried through every scene with their characters, starting each fight with full hearts, dodges and cooldowns.
  - **Victory:** the boss is defeated. A VICTORY panel on the left shows the fight time and each player's damage. Everyone stands up and can move; when all players stand in the gold circle on the right of the arena for 3 s, the game goes on to the next scene (the Lobby after the last one). Leaving the circle cancels the countdown.
  - **Defeat:** every player is downed at the same time. The DEFEAT screen shows the same stats; every player presses A / E to return to the Lobby (presses in the first half second are ignored).
  - **Discordance** starts at 0 every fight, rises over time and when players are hit, and drops with each successful Resonance. Numbers are per boss in `Assets/Tuning/Encounters/` (`BossOneDiscordance.asset`, `MafiaDiscordance.asset`, currently identical). There's no meter on screen yet, and bosses don't react to it yet.
  - Back in the Lobby, everyone keeps their character and stands at their spawn point, ready. Stand in the cyan ring to pick again; new players can join.

## 1. One-time setup on each machine

### Unity Smart Merge for scenes and prefabs

`.gitattributes` already tells git to merge Unity files (`.unity`, `.prefab`, `.asset`, `.meta`, ...) with a merge driver called `unityyamlmerge`. **Git doesn't share the driver itself through the repo**, so everyone has to define it once in their own git config. Without it, git falls back to a plain text merge, which can corrupt scenes and prefabs when they conflict.

Run these three commands once. Change the path if Unity is installed somewhere else.

```bash
git config --global merge.unityyamlmerge.name "Unity SmartMerge (UnityYAMLMerge)"
```

```bash
git config --global merge.unityyamlmerge.driver "'C:/Program Files/Unity/Hub/Editor/6000.3.24f1/Editor/Data/Tools/UnityYAMLMerge.exe' merge -h -p --force %O %B %A %A"
```

```bash
git config --global merge.unityyamlmerge.recursive binary
```

- **Finding your path:** in Unity Hub, go to *Installs* → the gear icon next to 6000.3.24f1 → *Show in Explorer*. The tool is `Editor/Data/Tools/UnityYAMLMerge.exe`. On macOS it's `/Applications/Unity/Hub/Editor/6000.3.24f1/Unity.app/Contents/Tools/UnityYAMLMerge`.
- **Checking it worked:**

  ```bash
  git config --global --get-regexp merge.unityyamlmerge
  ```

### Always commit `.meta` files

Unity creates a `.meta` file next to every asset and folder. It holds the asset's ID (GUID) and its import settings, and scenes and prefabs reference assets by that ID. Commit each `.meta` file together with its asset. If one is missing, Unity makes a new ID on other machines, and every reference to that asset breaks.

### Runtime debug menu

Press **F1** to open or close the mouse-operated debug panel. It is available in all builds. The game continues running; mouse attacks are suppressed only while the pointer is over the panel. Keyboard movement and other controllers remain active.

- **No cooldowns:** immediately clears current ability cooldowns and prevents new cooldowns. Attack phases, combo rules and other resource/action restrictions still apply. Disabling it restores normal cooldowns for future casts without restoring old timers.
- **Invincibility:** prevents damage to all players without reviving downed players or changing other immunity timers.
- **Infinite dodge:** allows dodging at zero charges without spending charges. Existing recharge continues; dodge timing, immunity and action restrictions remain unchanged.
- **Heal living players to full:** restores health globally, leaving downed players down.

Cheats also apply to newly joined players. Closing the panel or changing scenes preserves settings; starting a fresh play session resets them. Enable **Show hitboxes** and **Enemy / dummy hurtboxes** to see existing `CombatHurtbox` capsules as green filled outlines over the game. They remain visible when F1 closes the menu, work in release builds, and do not require Gizmos. **Player attacks** shows orange Guitar Primary, Defensive and Special impact areas; **Special zones** shows Primary’s outer sweet band and Special’s inner sweet circle in purple. Dashed outlines are historical snapshots, shown for 0.12 seconds by default, rather than continuously damaging hitboxes. They are captured at actual impact even on misses, remain fixed as the player moves, and expire on world time during hitstop. Special’s sweet circle tests the target’s ground-projected centre, not silhouette overlap. Secondary Strum uses a live orange preview of its actual swept capsule queries, including expansion, taper and collision thickness. The buffer is replaced each step and clipped to the accepted wall-stop fraction; solid outlines show the live query primitives, and the last step briefly remains dashed when the wave ends. Strum still uses world-space colliders, so projected overlap alone does not guarantee a hit. **Player hurtboxes** shows damage-receiving players in cyan, above attack previews. It hides downed and invulnerable players, including dodge/ability/revival immunity and the Invincibility cheat. The combat capsule derives from each player’s current CharacterController at a default 0.9× size, keeping the bottom at the same feet position. Tune its multiplier in `Assets/Tuning/Players/PlayerHurtboxTuning.asset`; world collision is unchanged. Enemy attacks must consume `Player.Hurtbox.GetWorldCapsule(...)` and apply damage through `Player.Health.TryTakeDamage(...)`; this mathematical hurtbox does not add a physics collider or automatically connect unfinished enemy attacks. Other classes’ attack previews are not wired yet. Tune colours, opacity, outline width, snapshot duration and dash spacing in `Assets/Tuning/Debug/DebugVisualizationTuning.asset`.

Automatic aiming considers active, living `BaseBoss` instances and damageable training targets with a `CombatHurtbox`, regardless of distance, layers or obstructions. It chooses the nearest eligible target, excludes players and REVs, and falls back to movement-facing when none exists. REVs require manual aim. Right-stick X/Y maps directly to world X/Z using the existing stick deadzone; releasing it returns immediately to Auto. Mouse aim projects the paired mouse cursor through the gameplay camera onto the horizontal plane at the player's feet. Both aiming modes continuously orient the resting Guitar and the character's left/right facing independently of movement. Auto follows the selected boss/dummy's current position each frame and refreshes nearest-target selection every 0.1 seconds by default (Auto Facing Refresh Interval in `PlayerAimTuning`). Manual takes priority. Active attacks retain their captured direction and still acquire fresh aim on activation. The keyboard/mouse cursor is `pointer` in Auto and `target` in Manual; textures and pixel hotspots are configured in `Assets/Tuning/Players/PlayerAimTuning.asset`. SVG sources and their 32×32 raster cursor copies live in `Assets/Art/UI/Cursors/`. Automatic selection is requested by abilities and the slower presentation refresh, with no per-frame target search or targeting physics query. Projectile range and collision still apply normally.

### Auto-target ground indicator

`GuitarPrimaryTest` has one reusable lock-on quad at each dummy's feet. Four arc segments per targeting player are interleaved evenly around the target (4/8/12/16 total arcs for 1/2/3/4 players). Colours follow player identity, irrespective of acquisition order. Only Auto targets show arcs: manual mouse/right-stick aim, downing, disabled players and lost input release that player's indicator. Returning to Auto or switching targets starts only that player's short oversized-to-normal, transparent-to-visible acquisition animation; existing players' animation clocks are retained when the angular layout redistributes.

Tune radius, thickness, coverage, arc count, rotation, opacity, acquisition duration/scale and optional identity-colour overrides in `Assets/Tuning/Combat/LockOnIndicatorTuning.asset`. **Editor Preview Players** is a bit mask: `1`, `3`, `7`, `15` preview the first 1–4 players without Play mode; return it to `0` to hide the preview. It is ignored at runtime. The indicator uses the existing `PixelWorldVFX` transparent path, with ordinary depth testing and no extra render pass.

For another boss, place `Assets/Gameplay/Combat/LockOn/Prefabs/LockOnIndicator.prefab` as a root in its encounter scene. Assign **Target** to the Behaviour selected by auto-targeting and **Ground Anchor** to a transform at its feet. Keep the quad out of a scaled boss hierarchy so its radius remains in world units. **Session** may reference the persistent GameSession; if omitted, the component resolves it once on startup. It observes the roster and player target-change events, never selects a target or applies damage.

## 3. Testing local multiplayer

**Each input device is one player** (up to 4).

- **Keyboard and mouse:** count as one player together, so two people can't share a keyboard right now.
- **Joining:** press the join button on each device to add another player.
- **Keyboard focus:** in the editor, click inside the **Game view** first, or keyboard and mouse input won't reach the game. Gamepads work without focus.

**Controllers:**
- **PlayStation 4 / 5:** USB or Bluetooth. To pair over Bluetooth, hold **Share + PS** until the light bar flashes, then add it in Windows Bluetooth settings.
- **Switch Pro Controller:** use **USB**, because Bluetooth detection is unreliable in Unity. Separate Joy-Cons are not supported.
- **Close Steam (or turn off Steam Input)** while testing. Otherwise it can take over PlayStation and Switch controllers.
- **Several controllers at once:** each controller pairs with the PC, and one PC can hold several at the same time. Four Bluetooth controllers on one built-in adapter may lag or drop out, so use USB cables (or a USB hub) for the 3rd and 4th.
- **A controller doesn't respond?** Open **Window → Analysis → Input Debugger** with it connected. If it isn't listed, Unity can't see it (usually Steam or Bluetooth).

### Dodge feedback

The shared `Player.prefab` includes `PlayerDodgeVFX`; Guitar and Flute inherit it. The standalone Trombone prefab is intentionally deferred. Move and press Space / the right trigger to activate a dodge; no incoming attack or successful evasion is required. Accepted activations spend a charge, pause that player for 0.05 s, then perform the existing dodge. Rejected inputs produce no effects. `IsDodging` invulnerability includes the startup pause, while charge recovery continues on world time. Distance, travel duration, easing and input behaviour are unchanged.

Tune **`Assets/Tuning/Players/PlayerDodgeTuning.asset`**. **Charge Recovery → Recharge Time** controls seconds per restored charge (default 7); spending the second charge does not restart the countdown. The shared prefab assigns this asset directly to `PlayerMovement`, independently of the VFX component. The standalone Trombone retains its existing prefab recharge value until migrated. Startup hitstop, afterimages and the directional flash have independent toggles. Snapshot count, spacing, lifetime and starting opacity are editable here. The afterimage fade curve is `(1 - progress)^3`. **Fade Steps = 0** follows the curve smoothly; positive values enable stepped opacity. Smooth fading keeps the same hard-edged, solid-colour silhouette. Color Multiplier modifies the player colour; the shader discards source RGB entirely and uses only sprite alpha, producing a solid silhouette. Snapshots capture the avatar frame/flip/transform, exclude weapons and shadows, and stay at their emitted world positions. Their lifetimes use world time; hitstop does not pause existing afterimage fades. Emission follows actual collision-limited XZ movement and skips the stationary freeze. The bounded pool has twice the configured per-dodge maximum; unusually long lifetimes recycle the oldest slots rather than allocating indefinitely. Disabling/destroying a player clears its pool; changing the active scene rebuilds it in the new scene.

The **Directional Flash** section controls its prefab, total duration (0.12 s), length (0.55), width (0.18), height (0.15), forward drift (0.08), colour, opacity and fade curve. It appears at activation, holding its first pose during local startup hitstop, then plays four held procedural poses on the player action clock. The fade curve is sampled once per pose, at 0, 0.25, 0.5 and 0.75 of the total duration. It stays near the captured starting position rather than following the player, with optional drift along captured dodge direction. The camera-facing quad aligns with the direction's camera-plane projection, renders on `PixelWorldVFX` before upscale and tests against world depth. The flat white/grey flash is visual only and has no collider or shadow casting. One inactive cached instance is warmed per player, reused on activation and cleared with that player's scene-local pool. Cancellation hides it immediately. It works with startup hitstop or afterimages disabled, without changing movement, i-frames or charge timing.

The **Distortion Shockwave** section controls its independent toggle, duration (0.25 s), initial/final radii (0.05 → 0.8 world units), ring thickness (0.12), height (0.15), strength (1 reference pixel), combined overlap limit (2 pixels), expansion curve and falloff curve. It starts at the captured dodge origin and expands on world time, including during startup hitstop. The ripple appears circular on screen; world-unit radii are converted using the orthographic camera. Two wave slots per player allow consecutive dodges to overlap; further emissions recycle the older slot. Cancelling travel does not retract an already-emitted disturbance; player/component disable and scene changes clear it.

`PC_Renderer.asset` includes `DodgeShockwaveRendererFeature`, which reads the existing pixel renderer's grid and distorts the composed gameplay image after transparencies, before post-processing and overlay UI. Characters, weapons, afterimages and world effects are included; Screen Space Overlay HUD remains outside the effect. World-space/camera-space labels are part of the gameplay image. One shared fullscreen pass combines up to eight waves, with no fullscreen target/draw when none are live and visible. Offsets use whole reference-grid pixels and point sampling, preserving colours and sharp edges. The effect can be subtle over uniformly coloured floors; use nearby silhouettes or floor detail when tuning strength.

For a quick check, dodge in `GuitarPrimaryTest`, dodge into its wall, spend both charges, and test two controllers together. The white directional flash and distortion shockwave complete the dodge feedback stages.

## 5. Testing Guitar

Open `Assets/Scenes/TestScenes/GuitarPrimaryTest.unity` and press Play. Join with E or the bottom gamepad face button. The first/third player uses Guitar; the second/fourth uses Flute. Move toward a dummy and hold Primary to cycle through the three sweeps. Primary slows normal movement to 20% throughout windup, active and recovery, while keeping dodge and other abilities locked. Its original forward lunge is added during Active; full walking speed returns after recovery. Moving closer gives normal hits; placing the target toward the outer part of the arc gives sweet-spot damage. Default damage is 2 normally and 3 in the sweet spot; dummies display the latest hit and total damage. The wall on the right can be used to check lunge collision and Strum blocking. Right-click / press the top face button to Strum. Alternate Secondary and Primary to play `S → P1 → S → P2 → S → P3`: Strum refreshes the combo continuation window without changing its step. Holding an ability retries it; holding both still gives Primary the existing input priority.

Press **E / the bottom gamepad face button (A/Cross)** as a joined Guitar player to use **Special: Overhead Smash**. It locks aim when pressed, pulls the guitar backward behind the player and holds it near shoulder height before a fast overhead downstroke. The ground indicator follows your slowed movement until impact, then stays fixed. Default timing is 0.9 s Windup → 0.12 s Active → 0.45 s Recovery; impact occurs 80% through Active. Walking runs at 20% throughout, with no lunge; dodge and other abilities remain locked. The 12 s cooldown starts on activation and continues during hitstop. Special resets the Primary combo.

The impact circle is centred 1 unit ahead, with a 0.75-unit outer radius and 0.25-unit inner sweet spot. Outer overlap deals 8 damage; the authored hurtbox's **ground-footprint centre (world X/Z, ignoring height) must lie inside the inner circle** for 16 damage. The sweet spot uses the ground circle directly; outer overlap retains the forgiving camera-projected hurtbox query. Raising the hurtbox does not shift its sweet-spot position. The collider fallback also uses its bounds centre in X/Z. A large hurtbox overlapping the inner circle without its centre inside receives normal damage. Targets without an authored hurtbox use a world-collider fallback. Each target is hit once; normal/sweet contacts request 0.06 / 0.1 s attacker-only hitstop, also holding the circular impact effect. Secondary empowerment raises these values to 12 / 24. Downing/cancellation stops the windup and indicator without an impact. REV/RES is deferred.

The three test dummies opt into camera-projected hurtboxes for **Guitar Primary and Special**. Enable **Gizmos** in each viewport (or toggle the `CombatHurtbox` entry in its Gizmos menu): the **Scene view shows the yellow 3D capsule**, while the **Game view shows its cyan projected outline over the artwork** when **Show Game View Preview** is checked in the hurtbox tuning asset. That checkbox defaults to off and controls all hurtboxes using the asset; the Game view's master Gizmos toggle must also be enabled. It does not affect the Scene-view preview or damage. Object selection is not required. These Editor previews do not appear in builds or change hit acceptance. A disabled hurtbox has no preview and cannot receive Primary or Special hits.

Tune all three through `Assets/Tuning/Combat/GuitarTestDummyHurtbox.asset`: **Center** is a 3D local-space offset, **Radius** sets the round cross-section, and **Height** is the total capsule height along local Y, including both rounded ends. The optional Anchor supplies position, rotation and scale; otherwise the component uses its own transform. Height scales along local Y, radius uses the larger absolute X/Z scale, and the capsule becomes a sphere when height is less than its diameter. The dummy defaults (radius 0.5, height 2, centre zero) follow their existing scaled capsule geometry. Adjust the asset while checking both previews to match the vulnerable visible body, including camera-facing sprite projection. The same world-space endpoints/radius supply both previews and combat queries; the Game-view preview has no independent shape settings. These are authored combat volumes, not pixel-perfect sprite outlines.

At Primary's initial impact, the attack compares the capsule and the initial crescent in the fixed orthographic camera's view. Apparent overlap can hit even when their world-space shapes are separated in depth. A hurtbox overlapping both the normal and sweet bands takes normal damage; only overlap confined to the outer band gets sweet-spot damage. The initial crescent's inner hole, angular edges and stretched reach still apply. Later smear poses cannot hit. Hurtboxes do not change physical world collision, and disabling one stops projected Primary hits rather than restoring the object's world collider as a damage shape. Targets without `CombatHurtbox` keep existing world-space detection. Secondary, other instruments and REV/RES still use their existing world-space queries; migration is separate. Projected queries do not provide wall occlusion and require a downward-facing orthographic gameplay camera.

Primary requests attacker-only hitstop on a valid melee contact: Each entry under **Attack → Combo** has its own **Hitstop Duration** and **Sweet Spot Hitstop Duration**: defaults are 0.04 / 0.06 s for the first strike, 0.05 / 0.075 s for the second, and 0.06 / 0.09 s for the third. A miss does not pause; an area hit resolves every target once, then uses the longest applicable duration instead of adding pauses. Set both durations on a swing to 0 to disable its feedback. The attacker stops walking/lunging, its attack phase, weapon animation and smear poses pause, and the local action clock resumes without a movement or animation catch-up jump. Health, cooldowns, UI, impact particles, enemies, other players and launched waves continue. Hitstop adds no invulnerability. Secondary/ranged hits do not request it.

Other melee classes can call `Player.Hitstop.Request(seconds)` after resolving contact. Use `Player.Hitstop.ActionTime` for action phase timestamps and `ActionDeltaTime` for local animation progress; keep cooldown/health/world-effect clocks on normal Unity time. `IsStopped` exposes the pause, and `Clear()` ends it without rewinding action time. `Player` ticks the clock before routing input and movement; callers must not tick it again. Overlapping requests keep the longer remaining duration. Ranged attacks must not request attacker hitstop. Cancel your action and clear its pause on cancellation; the player clears it on down/disable. No change to `IHittable`/`HitInfo` is needed.

Player sprites use `Assets/Rendering/PlayerShadows/PlayerShadowReceiver.mat` to receive environment and character shadows while excluding weapon shadows from the main directional light. The world still receives normal weapon shadows. Player shadow sampling follows the original sprite mesh geometry to avoid false self-shadowing while keeping the body’s ground shadow. `PC_Renderer.asset` runs `PlayerShadowRendererFeature`; its settings live in `Assets/Tuning/Rendering/PlayerShadows.asset` (2048 atlas by default). Set an instrument weapon's renderer child to **WeaponVisual (layer 13)** and enable Cast Shadows; keep its gameplay colliders and effects on their existing layers. Guitar is wired, and player receiver materials are assigned on the base Player and standalone Trombone prefab. No scene-light changes are needed. Guitar's resting and attack materials enable **Environment Shadows Only**, selecting a separate weapon receiver atlas that excludes `SpriteVisual` character sprites and `WeaponVisual` casters. The guitar still receives environment shadows, while characters and weapons retain their normal ground shadows. `PlayerShadows.asset` also contains **Weapon Atlas Resolution** (1024 by default) and **Weapon Excluded Caster Layers**. This adds one additional caster cull and atlas render; use the `Weapon Shadows (Environment Only)` profiler marker when assessing cost. Character/enemy sprite renderers must use the excluded visual layer for this filtering to apply. Additional point/spot-light shadows currently retain ordinary URP behaviour. The extra shadow atlas and caster cull add rendering cost; profile the named Player Shadows pass before raising resolution. Disabling the feature restores normal shadow reception.

Player body animation uses the base prefab’s Animator and `Assets/Gameplay/Players/Animation/Player.controller`. Idle (frames 0–1), Walk (8–11) and Run (12–15) loop at **8 FPS** and switch based on actual horizontal movement, including collision blocking. `Assets/Tuning/Players/PlayerAnimationTuning.asset` sets the idle cutoff (0.05 units/s) and run threshold (above 1.5 units/s). The Animator pauses with the player’s hitstop. Attack (4–5), TakeDamage (6–7), Jump (24–31) and Death (36–39) are prepared as non-looping 8 FPS clips and disconnected states; they are not triggered yet. Edit frame sequences and playback timing in Unity’s Animation window. Guitar Primary, Secondary and Special override locomotion with held body poses: **Windup uses literal sheet frame 4, Active frame 2, Recovery frame 0**. These are the AttackWindup/AttackActive/AttackRecovery clips, selected by the controller’s `AttackPhase` parameter using the ability’s existing timings. Completion/cancellation resumes normal locomotion; hitstop holds the current attack pose. Horizontal movement input flips the body sprite, retaining facing when stationary or moving vertically.


For integration, open `Lobby`, select Guitar, and attack the mic dummy. The same selected Guitar player and controller pairing continue through the cutscene into `Game`.

Tune Guitar in **`Assets/Tuning/Instruments/Guitar/GuitarTuning.asset`**. Its five foldout sections contain the shared configuration used by every Guitar player:

- **Attack**: the three windup/active/recovery timings, sweep angles, lunges, Movement Speed Multiplier, per-strike reach multipliers, combo reset/cooldown, base reach/inner radius, stretch axis/depth stretch, hit thickness, sweet-spot radius, damage, per-strike normal/sweet Hitstop Duration, Impact Fraction and easing curves. Impact Fraction is normalized over Active (0.5 is halfway); at that instant the full crescent hits once and appears. Its centre stays at that impact position despite the remaining lunge. Movement Speed Multiplier defaults to 0.2: normal directional movement runs at 20% speed throughout Primary's windup, active and recovery, including swings with zero lunge distance. Set it to 0 to lock walking or 1 for full speed. Live input steers only that slowed walking, preserving analog input strength. The captured forward lunge keeps its own distance, timing and easing and is added during Active. Aim remains captured, and the impact area stays at its initial impact position. Secondary has its own independently tuned Movement Speed Multiplier. The third strike defaults to 1.4× reach; its sweet-spot radius scales by the same multiplier. Depth Stretch defaults to 1.5 along world Z (Stretch Axis `(0, 1)`), elongating the hit area, inner hole and sweet-spot band together to compensate for the flat world geometry's foreshortening. Set it to 1 for a circular sector. The axis is fixed in arena space, independent of player aim and the rendering camera.
- **Secondary**: wave prefab, Movement Speed Multiplier, windup/active/recovery, cooldown, damage, next-Primary-or-Special multiplier, travel duration/range, movement/growth/fade curves, spawn offset, curved front size/angle/tip taper, collision thickness/mask, strum pose/offset/grip, vibration amplitude/frequency/decay and backstep distance/easing. Defaults are 0.2 s windup + 0.12 s active + 0.08 s recovery, 0.5 s cooldown, 1 wave damage and a 1.5× empowerment multiplier. Travel Duration defaults to 0.75 s and controls the projectile independently of the short casting action. Travel Curve maps normalized lifetime to normalized travel distance; its default launches quickly and slows down. Growth Curve scales the crescent radius (default 1 → 1.8), keeping line thickness steady; collision expands with the visible front. Fade Curve holds opacity through the first 65% of lifetime, then fades to zero. Range measures the wave centre's travel; Spawn Offset positions its initial front tip relative to the player. The wave inherits Attack's arena-space stretch. Normal movement runs at Secondary's Movement Speed Multiplier (default 0.2) throughout windup, active and recovery, while dodge and other abilities remain locked. Walking input and its strength stay live; the captured-direction backstep is added independently during Active, and zero-backstep casts still allow slowed walking. Finishing or cancelling restores normal walking speed. Windup brings the guitar across the torso into a playing pose mirrored left/right using captured aim. On wave release it vibrates along camera-up while the player retreats opposite the captured aim. Strum Amplitude defaults to 0.04 world units (two pixels at 50 PPU), Frequency to 14 Hz, and Decay to 2: displacement is a sine wave multiplied by `(1 - progress)^decay` over Active plus Recovery. Recovery settles toward the shoulder pose as vibration fades. The visual offset uses the player action clock, holds during hitstop and resets on cancellation; it never changes the wave or damage. Backstep Distance defaults to 0.15 units; the motion lasts for Secondary Active and uses Backstep Easing through the shared CharacterController displacement API. Walls constrain it, and cancellation/downing stops it. The wave launches at Active's start. Recovery settles the weapon after the strum/backstep; inputs unlock after Recovery while the wave continues travelling.
- **Special**: windup/active/recovery, cooldown and impact fraction; forward distance, outer/inner radii, impact height and legacy collider-query height/mask; damage and sweet-spot multiplier; movement slowdown and hitstop; raise/hold fraction, overhead angles, grip heights, Windup Backward Offset and easing; Windup Shake Angle / Frequency control a stepped guitar-only tremble that strengthens toward release (set angle to 0 to disable); indicator colours/opacity and impact lifetime. Geometry is snapshotted at activation, and the same radii supply damage and the visible circles. The raised weapon holds behind character sprites during Windup, then uses the normal attack material for the downstroke.
- **Weapon**: grip offset, separate Resting Grip Point / Attack Grip Point in sprite-local units, Resting Angle Offset, position/rotation response, sprite angle and scale. The resting body points opposite movement facing with a configurable screen-space angular offset (Resting Angle Offset, default 20 degrees clockwise). Facing left mirrors it counterclockwise; diagonals use their left/right screen-facing half, while straight up/down use clockwise. Up faces the body down-left, right up-left, down up-right, and left up-right. Resting Grip Point starts at `(0, 0.1)` inside the grey neck; Attack Grip Point keeps the original `(0, 0.45)` outside the sprite. Windup blends between grips using the position response; the active swing uses the exact attack grip, and returning to idle blends back. Grip Offset controls the attachment position; the old Shoulder Lift direction bias is removed. Idle depth geometry follows the same smoothed visible axis; attack swing angles are unchanged. The weapon keeps its follow-through between combo strikes, then blends back to the shoulder pose. Strum uses its own torso-held playing pose and damped vertical vibration; its pose and vibration controls live under Secondary. While resting, `GuitarRestingWeapon.mat` draws at queue 2449 with ForwardLit depth writes off, before avatar sprites at queue 2450. This puts the entire resting guitar behind overlapping character bodies, including other players, while retaining world depth testing and floor visibility. Primary/Secondary poses and held combo follow-through use `GuitarAttackWeapon.mat` at reserved queue 2500 with depth writes off. The renderer draws these weapons after character sprites against a separate world-only depth buffer, so the entire guitar covers characters while world geometry still occludes it. Special keeps its held Windup behind characters and uses this front pass for Active/Recovery. Character-to-character depth remains unchanged; subsequent transparent passes retain character depth, which does not include front weapons. Both materials are prefab references; neither is modified at runtime. The weapon geometry stays flat on XZ for depth testing. `2DSpriteMat` projects the image toward the camera and rotates it around the configured grip; no camera-facing transform or camera-depth lift is applied.
- **VFX**: Strum body/rim/tail colours, tail length/opacity, breakup scale, flow speed and stepped fade levels, plus Primary's four pose durations (X broad slash, Y follow-through, Z broken crescent, W endpoint streaks), body/sweet-spot colors and impact colors/sizes. The `SlashSmear` child renders a flat XZ mesh with four held shapes and hard color bands. Pose 3 has a flat leading edge and torn trailing edge; the final pose keeps streaks in the latter half of the swing. The initial pose uses the exact impact centre, inner/outer radii, angles and sweet-spot radius supplied by GuitarAbilities; later poses are cosmetic afterimages and cannot hit. The shader undoes the supplied stretch before comparing distance with that same sweet-spot radius, so the color boundary follows the gameplay ellipse. Decorative edge clipping does not change the underlying sector.

Strum grants a single non-stacking empowerment on launch, even if it misses. It has no expiry and is consumed when the next Primary or Special successfully starts, applying to every target hit by that strike and multiplying sweet-spot damage too. A missed Primary or Special still spends it. Downing, disabling or cancelling the player clears it. The wave pierces enemies once each, ignores players, stops at solid world geometry and expires when its travel duration or fade finishes. Swept queries include both travel and expansion between frames. Its bold leading crescent is the hit volume; the darker fragmented tail is cosmetic. The dedicated Strum shader uses flat warm colour bands, a crisp rim, hard-edged breakup and stepped opacity, with no bloom or soft colour gradient. Already-launched waves continue if the caster is downed, and belong to the encounter scene rather than the persistent player root.

The earlier controlled DPS comparison predates the separate Secondary recovery phase. Recheck Primary-only versus alternating Strum/Primary after timing or damage changes; that earlier measurement does not validate the current cadence.

The `GuitarPlayer` prefab assigns the same tuning asset to `GuitarAbilities`, `GuitarWeaponVisual` and `GuitarVFX`. Those components keep their own runtime state; tuning the asset affects all users, while cancelling one player does not affect another. Renderer/transform wiring stays on the prefab. Create additional Guitar tuning assets through **Assets > Create > Game50033 > Tuning > Guitar** when an intentional configuration variant is needed.

The weapon sprite is imported directly from the unpadded 20×39 `Abilities/Guitar/Art/guitar2.aseprite` source at 50 pixels per unit with a centred import pivot. `GuitarWeaponVisual` holds the grey neck at rest and places the attack grip three pixels above the artwork (`Attack Grip Point = (0, 0.45)`). It uses an outward angle of −90° for the upright image. Sprite Scale defaults to 1; 50 PPU matches the test scene’s 360-pixel reference height and ortho size 3.6 before deliberate animation scaling. Defensive still returns false for Guitar. Primary, Secondary and Special do not create or consume Reverberations.

### Weapon occlusion and floors

In `GuitarPrimaryTest`, the training floor uses the **Floor** layer (14). `PC_Renderer` includes it in World Layers and Toon Layers, and excludes it from weapon depth through **Floor Layers**. Guitar depth comes from a world-upright plane through its grip; the floor never occludes resting or attacking guitar artwork. Obstacles still occlude it. Characters and other effects retain normal floor depth.

For another arena, assign only its floor renderers to the Floor layer and include that layer in the camera/light and world rendering masks. The current Floor layer uses the toon override; preserve the arena's intended material policy when configuring masks. Keep walls, dummies and other occluding objects on non-floor layers, weapon sprite children on WeaponVisual (13), and weapon materials' depth writes disabled. Floors and walls combined in one mesh must be separated to apply this policy. Other scenes have not been migrated.

### Guitar Defensive — sweep and backstep

Use **Q** on keyboard or the gamepad's **east face button** (Xbox B / PlayStation Circle). Holding retries on cooldown, with Defensive taking priority over held offensive attacks. It can interrupt Guitar Primary, Secondary or Special during Windup and Recovery, but cannot interrupt Active, itself or a dodge. Dodge's existing cancellation rules are unchanged.

Defensive grants invulnerability immediately through Windup and Active, sweeps forward once, and backsteps opposite the aim captured at activation. Slowed walking adds drift throughout the animation. The character repeatedly flashes a white overlay during immunity, ending at Recovery; local hitstop holds the attack, immunity and flash together. All targets take the same damage, with no sweet spot. It preserves and refreshes Primary continuation and leaves pending Secondary empowerment available. Cancelled Primary Windup retries the same hit; cancelled Recovery continues to the next. Spent cooldowns and consumed empowerment are not refunded.

Tune **Defensive** in `Assets/Tuning/Instruments/Guitar/GuitarTuning.asset`: starting Windup/Active/Recovery are **0.08 / 0.2 / 0.2 s**, cooldown **5 s**, backstep **0.4**, damage **2**, and hitstop **0.04 s**. Hit area, movement multiplier, easing/weapon curves and flash frequency/opacity/duty cycle are independent settings. Invulnerability duration follows Windup + Active. Test cancellation in both allowed phases, an attempted cancellation during Active, single-hit damage, a wall-limited backstep and two controllers independently.

### Melee smear pacing

Primary and Defensive each use **Impact Fraction** in Guitar tuning: **0.5** makes damage and the initial crescent appear halfway through Active. The four held smear poses then span one full Active duration, so slowing the swing also lengthens the smear; final streaks can extend into Recovery. **VFX → Melee Smear → Frame Weights** controls their relative proportions rather than seconds. Each emitted smear snapshots its own timings; changing tuning or starting another swing does not retime existing smears. Local hitstop still pauses the weapon and smear together. Special and Secondary timing are unchanged.

## 6. Testing Cymbals Primary

Open `Assets/Scenes/TestScenes/CymbalsPrimaryTest.unity` and press Play. Join with E or the bottom gamepad face button; every join slot uses Cymbals. Stand about one unit from a dummy and hold Primary to run the chain: right forward bash, left slash, right slash, left slash, then both cymbals clash. Default damage is 1 per hit and 2.5 for the clash. Dash (Space / right trigger) during a hit's recovery and the next press continues with the following hit. Dash during a windup and that hit is cancelled; the next press repeats it. Select the player in the Scene view to see gizmos: the blue ring is every possible hitting point and the yellow circle is the damage area.

Cymbal Throw is in the same scene. Stand about 2.5 units from a dummy and press Secondary (right click / top face button). The cymbal spins out, slows to a stop at the apex, flashes, then speeds back to you. It hits on the way out and on the way back (1.5 each by default). While it flies you can move and dash, but not use Primary. Press Secondary once more while it flashes to drop an orange Burst Reverberation at the cymbal and dash to it (2 damage to anything on the way). Pressing again before or after the flash only drops the Burst, and the cymbal keeps flying.

Crash is Special (E / bottom face button). Both cymbals rise overhead and slam on the hitting point, and slanted waves sweep forward through a triangle (3 long, 3 wide at the far end by default). It deals 4 damage to everything in the triangle and sets off other players' Reverberations inside it. You have 2 charges, refilled one at a time (6 s each). Note: in this test scene, the button that joins you is also Special, so your first Crash charge may be spent on joining.

Parry is Defensive (Q / right face button). The `Parry test turret` behind the dummies fires a grey ball at the nearest player every 1.2 s; each one that touches you deals 1 damage. Auto can aim toward the training dummies; use mouse Manual mode (Left Shift) or the right stick when you want to aim elsewhere. Parry retains that initial direction for its duration. Press Defensive and both cymbals spread out in front and shake, while a glowing arc marks the edge of the cone for 2 s: every ball entering the cone is destroyed, and the first one gives you a Crash charge. Shots from other directions still hit. A dash ends the parry early; either way the 7 s cooldown starts when it ends. Boss projectiles need the `BossProjectile` tag to be parried.

Tune Cymbals in **`Assets/Tuning/Instruments/Cymbals/CymbalsTuning.asset`**:

- **Combo / Hits**: per-hit windup, approach, follow-through and recovery times, damage, lunge, and for each hand whether it swings plus its start and end pose. A pose is X = degrees around the player relative to the aim (+ is aim-right) and Y = distance. Damage lands when the approach ends, and the swinging cymbal is always on the hitting point at that moment, whatever the poses.
- **Combo / Hitting point**: `hitDistance` and `hitRadius` (the damage circle on the ground plane), shared by all five hits. `hitHeight` is only where the cymbals meet visually. `hitColumnHeight` is how tall the damage area is, measured from the feet, so tall or raised targets are still hit. Trigger colliders never count as hits.
- **Throw**: windup, range, outbound and return time, and speed curves (by default it slows to a stop at the apex, then speeds up back to you). Also cooldown, flight damage and radius, apex window (total seconds around the apex in which a recast also dashes), the Burst Reverberation prefab and strength, dash speed, catch offset and damage, spin speed and minimum spin, and the apex flash.
- **Parry**: duration, cooldown, raise time, cone angle and range, the projectile tag, Crash charges rewarded, the parry effect and cymbal pop, the stance (cymbal spread, shake amplitude and frequency), and the parry line (material, width, segments, colour, glow rate, dim brightness, glow width).
- **Crash**: max charges and recharge time, windup, impact hold and recovery, damage, triangle length and far-end width, and the waves (material, count, duration, stagger, slant, width, colour).
- **Debug**: Show Hitboxes draws every Cymbals hit area as gizmos in play mode (turn on Gizmos in the Game view toolbar); areas real hits used flash red for Hitbox Flash Time.
- **Weapon**: guard pose, clash spacing, easing curves per phase, sprite and impact scale. **Slash trail** sets the streak behind each swinging cymbal: material (`Abilities/Cymbals/Art/CymbalsTrail.mat`), time (length), start and end width, and colour.
- **Combo / Hits / Big Hit** chooses the big-hit style of the hit effect; it's on for the clash.

Hit feedback is in **`Assets/Tuning/Instruments/Cymbals/CymbalsHitEffect.asset`**, an asset of the shared **Hit Effect** type (**Assets > Create > Game50033 > Tuning > Hit Effect**). Every section has a normal and a big style:

- **Impact sprite**: a horizontal strip PNG of equal-width frames, plus frame count, frame duration, scale and tint. The placeholders are `Abilities/Cymbals/Art/CymbalImpactSpark.png` (4×20 px) and `CymbalImpactShockwave.png` (4×36 px).
- **Particles**: an optional particle prefab for normal and big hits.
- **Damage numbers**: a glyph strip (`Combat/HitEffects/Art/DamageDigits.png`, 5×7 px per glyph, in the order `0123456789.`), plus colour, scale, rise, lifetime, sideways jitter and spawn height.
- **Sound**: clips picked at random, volume, pitch range, and an optional mixer group.

Leave a section empty to turn it off. To redraw the art, keep the same strip layout, or change the frame count or glyph order to match the new strip.
